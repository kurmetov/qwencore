# Спекулятивный decode на MTP-голове — 2026-09-16

> **Одиночные точки одной сессии, без доверительных интервалов.** Сравнение с
> vLLM здесь снято до появления протокола
> [`docs/11-experiments.md`](../../docs/11-experiments.md): один-два прогона на
> точку, без ротации порядка вариантов и без bootstrap CI, на частично занятой
> карте. Эти множители отменяются прогоном comparison suite и не должны
> цитироваться как результат проекта. Условия каждой точки — ниже по тексту.

Черновики предлагает голова из чекпоинта, проверяет их модель одним проходом
по весам. Выход обязан совпадать с обычным greedy — это проверяется флагом
`--verify` и держится на всех прогонах.

## Итог

`speculate --max-new 96`, batch 1, промпт из 9 токенов:

| глубина черновика | tok/s | принято на шаг | токенов за шаг |
|---:|---:|---:|---:|
| обычный greedy | 82.3 | — | 1.00 |
| 1 | 122.0 | 0.88 | 1.88 |
| **2** | **124.2** | **1.58** | **2.58** |
| 3 | 106.2 | 1.53 | 2.53 |
| 4 | 91.2 | 1.43 | 2.43 |

Лучшая точка — два черновика: **1.51x** к обычному decode. На других промптах
1.55-1.60x. Против vLLM 0.28 на той же карте (50.4 tok/s) это **2.5x**.

## Из чего складывается шаг (глубина 2)

| | мс |
|---|---:|
| черновики (2 x 1.48) | 2.96 |
| проверка модели, 3 строки | 17.14 |
| фиксация состояния | 0.23 |
| **итого** | **20.3** |

Черновик: 0.64 мс сама голова (849 МБ BF16, 1320 из 1790 ГБ/с) плюс 0.82 мс
словарная проекция (1.27 ГБ). Словарь дороже головы.

## Почему глубже трёх не окупается

Проверка k+1 строк стоит **не как шаг decode**: 13.75 мс на двух строках,
17.14 на трёх, 19.06 на четырёх, против 12.2 мс у обычного шага. Дело в
узких формах NVFP4: `nvfp4bench` меряет W4A16 на 1513 ГБ/с при одной строке,
1078 при трёх и 840 при четырёх, тогда как W4A4 идёт ровно около 1000 при
любой ширине. То есть каждая добавленная строка проверки стоит около 1.8 мс,
хотя веса читаются один раз.

**Это и есть следующий рычаг.** Если бы проверка трёх строк стоила как шаг
decode, глубина 2 давала бы 2.58 / (12.2 + 2.96 + 0.2) = **168 tok/s**, то
есть 2.05x вместо 1.51x. Нужен batch-нечувствительный W4A16 на 2-8 строк.

Второй по величине — словарная проекция черновика: 0.82 мс из 1.48. В NVFP4
словарь занял бы 0.64 ГБ вместо 1.27.

## Как устроена проверка

Состояние DeltaNet рекуррентно, поэтому откатить его нельзя — можно только не
трогать. Проверка идёт по **черновому слоту**: перед ней состояние
последовательности копируется туда (81.4 МБ, 0.05 мс), k+1 строк проходят
стек на нём, а настоящее остаётся на месте. Дальше:

- приняты все черновики — черновое состояние переносится обратно копией;
- принята часть — conv и скан доигрываются на настоящем слоте по сохранённым
  входам миксера (48 слоёв x до 8 строк x 16480 значений, 12.7 МБ), и второго
  прохода по весам это не стоит.

Фиксация в сумме 0.23 мс на шаг, то есть чуть больше процента.

KV-страницы пишутся сразу всем k+1 строкам: отвергнутые позиции перезаписывает
следующий шаг, длина контекста растёт только на принятые токены.

## Попутные правки

- Узкий prefill (до 128 строк) теперь выбирает ядро проекции тем же правилом,
  что decode. Раньше он всегда шёл W4A4, и шаг проверки стоил 24 мс вместо 17.
- Короткий отрезок скана (меньше 192 токенов) считается рекуррентной формой:
  у чанковой шесть подготовительных запусков на слой, и на трёх строках они
  дороже самого скана.

## Отвергнуто замером

Расширение W4A16 на 5-8 строк: по `nvfp4bench` при batch 4 W4A16 даёт 840
ГБ/с против 1000 у W4A4, дальше разрыв только растёт — выигрыша нет. Правка
успела сломать промпты длиной 5-8 токенов (слитая swiglu-ветка принимает
только четыре строки) и откачена.
