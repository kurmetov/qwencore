# Раскладка чекпоинта QUASAR-NVFP4

Источник — `QUASAR-QAT/Qwen3.8-27B-QUASAR-NVFP4` на Hugging Face; качается
`./scripts/fetch-checkpoint.sh` (переопределяется через `REPO` и `DEST`,
докачка поддерживается). Разбор раскладки:

`cargo run -p qwc-model --bin inspect`

## Формат квантизации

На каждый из **496** квантованных linear-слоёв приходится четыре тензора:

```
{prefix}.weight_packed        U8        [out, in/2]     два fp4 (e2m1) в байте
{prefix}.weight_scale         F8_E4M3   [out, in/16]    шкала на блок из 16
{prefix}.weight_global_scale  F32       [1]
{prefix}.input_global_scale   F32       [1]             W4A4: активации тоже fp4
```

496 = 64 MLP-слоя x 3 + 16 attention x 4 + 48 linear_attn x 5.

## Что уточнилось против первоначального разбора config.json

| | |
|---|---|
| `self_attn.q_proj` | `[12288, 5120]`, то есть 24 x 256 x **2**. Выходной гейт (`attn_output_gate`) вшит в ту же проекцию, отдельного тензора нет |
| `self_attn.q_norm` / `k_norm` | `[256]` — в модели есть **QK-норма на голову**, в config.json это не видно |
| `linear_attn.in_proj_qkv` | `[10240, 5120]` = 2048 (q) + 2048 (k) + 6144 (v) одной проекцией |
| `linear_attn.in_proj_z` | `[6144, 5120]` — гейт вынесен отдельно |
| `linear_attn.in_proj_a` / `in_proj_b` | `[48, 5120]` — проекции для alpha и beta, по одному числу на v-голову |
| `linear_attn.conv1d.weight` | `[10240, 1, 4]` — depthwise causal conv по объединённым q, k, v |
| `linear_attn.norm.weight` | `[128]` — RMSNormGated по `v_head_dim` |
| MTP-голова | **не квантована**, 15 тензоров bf16: `fc [5120, 10240]`, две пре-нормы, один полный слой |

## Проверка модели памяти

Сверка всех 2354 тензоров с compile-time константами архитектуры прошла **без единого
расхождения**. Это одновременно проверяет и загрузчик, и правильность разбора модели.

| | предсказание | чекпоинт |
|---|---:|---:|
| веса NVFP4 (packed + шкалы) | 13.68 GB | **13.70 GB** |
| наша загрузка в VRAM | 17.08 GB | **17.09 GB** |

Раскладка на диске:

```
веса NVFP4 (packed)     12.18 GB
поблочные шкалы fp8      1.52 GB
нормы и мелочь           0.01 GB
embed_tokens bf16        2.54 GB
lm_head bf16             2.54 GB
MTP-голова bf16          0.85 GB
не нужно (vision)        0.92 GB   333 тензора
итого                   20.56 GB
```

**Фора над baseline: 3.46 GB** — vision tower не грузим вовсе, `lm_head` и
`embed_tokens` переводим в fp8. Под кэш остаётся 12.89 GB против 9.4 GB,
это 11 против 8 последовательностей на 32K.

## Принцип загрузчика

Архитектура известна на этапе компиляции, поэтому расхождение формы — это
**ошибка загрузки, а не повод подстроиться**. Универсальный движок примет
любой тензор и упадёт позже, в кернеле, с невнятной диагностикой.
